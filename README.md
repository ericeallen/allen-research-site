# allen-research.com

The source of Eric Allen's personal site: five static pages (home, publications,
software, talks, CV) generated by a small Python program with no dependencies.
The pages load no scripts, no web fonts, and nothing from third parties.

## Build and preview

Requires Python 3.12 or later.

```
python -m sitegen                              # writes _site/
python -m http.server 8000 --directory _site   # http://localhost:8000
```

Links inside the site are relative, so the same build works at the custom
domain, under a GitHub project path, and on a local server.

## Change the content

Everything the site says is in `sitegen/content.py`, as typed values. To add a
paper, add a `Publication(...)` at the top of its group in `PUBLICATIONS`; to
feature it on the home page, add its title to `SELECTED_TITLES`. The CV sections
(`EXPERIENCE`, `TEACHING`, `EDUCATION`, `PATENTS`, `AWARDS`), the projects on the
software page (`PROJECTS`), and the talks page (`TALKS`, `SLIDE_DECKS`,
`COURSES`) work the same way. Lists appear on the page in the order written.

Two things are derived rather than written twice:

- The employer in the home page's search metadata is the `EXPERIENCE` role whose
  end year is `None`. The sentence naming the employer in `HOME_INTRO` is prose
  and must be edited by hand.
- When the blog is live, set `SITE.blog_url` and a Blog link appears in the
  navigation.

Text is plain strings and `Link(text, url)` values. Internal links are written
from the site root (`/software/#fortress`). Text is escaped when rendered, so
content cannot contain HTML.

Images go in `static/img/`, slide decks in `static/slides/`, videos in `static/demo/`. The build fails if
the content names a file that is not there.

## The Towel demo video

The video on the software page is rendered from a real run of Towel, in two
steps. Re-run both after a Towel release changes its output.

```
pip install "code-towel[format,types]"
python tools/towel_demo/capture.py     # runs towel on example/accounts.py

cd tools/towel_demo
npm install --no-save puppeteer-core   # once
node record.mjs                        # needs Chrome and ffmpeg
```

`capture.py` runs `towel preview` under a pseudo-terminal three times, checks
that the output is stable and the input untouched, and writes the output and
the median run time to `capture.json`, plus the transcript the site links to.
`record.mjs` draws each frame from that file with `render.html` and encodes
`static/demo/towel-preview.mp4` and its poster. The terminal text and the wait
are the run's own; the diff colors, highlights, and captions are added by
`render.html`.

## Checks

```
python -m unittest discover tests   # links, headings, metadata, determinism
uvx ruff check . && uvx ruff format --check .
uvx mypy
python tools/check_links.py         # external links; needs the network
```

The tests build the site into a temporary directory and check every page:
internal links and fragments resolve, each page has one `h1` and no skipped
heading level, titles and descriptions are present and distinct, images carry
alt text and dimensions, and two builds are byte-identical.

`check_links.py` reports `ok`, `DEAD`, or `unverified`. Several publishers
(ACM, Medium, LinkedIn) refuse automated requests; those links show as
`unverified` and need a click to confirm.

## Layout

```
sitegen/model.py     the shapes of the content (frozen dataclasses)
sitegen/content.py   the content
sitegen/markup.py    escaping and inline rendering
sitegen/pages.py     content to HTML, as pure functions
sitegen/build.py     writing files; the only module with side effects
static/              stylesheet, favicon, images, slide decks (copied as is)
tests/               checks on the built site
tools/               the external link checker and the demo video's generator
```

## Publish

The site is built for GitHub Pages. `.github/workflows/pages.yml` runs the
tests, builds, and deploys on every push to `main`.

1. Create a public repository on GitHub and push `main`.
2. In the repository's Settings, under Pages, set the source to GitHub Actions.
3. Check the build at `https://<user>.github.io/<repository>/` before touching
   DNS. Relative links make the site work there.
4. In the DNS zone for `allen-research.com`, replace the apex `A` record with
   GitHub's four (`185.199.108.153`, `185.199.109.153`, `185.199.110.153`,
   `185.199.111.153`), and add a `CNAME` for `www` pointing to
   `<user>.github.io`. Remove the domain forwarding rule at the registrar.
   Leave the `MX` and `TXT` records alone: they carry the domain's email.
5. In Settings, under Pages, set the custom domain to `allen-research.com` and,
   once the certificate is issued, turn on Enforce HTTPS.

Confirm GitHub's current addresses in its Pages documentation before step 4.
